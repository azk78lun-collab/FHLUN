# Lun 分布式服务器集群（API v3）

此目录由 `lun.sh` 的“分布式服务器集群”菜单管理。模块默认不安装；启用后每台 VPS 运行同一份 `lun_cluster.py`，每个成员保有自己的身份私钥和 mTLS 证书。不存在控制器/受管角色，也不共享或迁移 CA 私钥。

## 安全与一致性

- 每个成员签名自己的事件链；事件包含作者序号、前序哈希与逻辑顺序，重复、篡改和过期重放会被拒绝。
- 成员之间仅接受结构化动作白名单，绝不接收任意 Shell 文本。
- 一次性 `lunjoin://` 加入地址只能使用一次，15 分钟后失效。加入后任意可信成员都可管理其它成员。Shell 只把后端 `nodes` JSON 明确标记为 `trusted=true` 的记录作为远控、CDN 同步和自动更新目标；旧记录的角色或状态文字不能替代信任证明。
- 联邦数据按需同步：启动、手动同步、协议重建后的快照发布和订阅缺失补齐都会触发同步；另外在现有联邦服务内每天轻量巡检一次，不新增服务或长连接。订阅 GET 由 `lun-agent` 先返回最近可信聚合文件，再异步调用 `subscription-access`；同一 Token 30 秒防抖，网络同步不得阻塞 HTTP 响应。
- 服务启动、立即同步和状态修复会按地址族通过固定 HTTPS 探测源交叉确认本机公网 IPv4/IPv6。任一地址族至少两个结果一致后才公布，双栈同时显示且 IPv4 优先。变化由节点本人签名 `node.metadata` 并以 `1→10→100` 两层有界方式广播；未变化时不产生事件也不联系成员。
- 联邦监听自动使用 IPv4/IPv6 双栈；TLS 握手移入独立线程并设置 8 秒上限，监听队列扩大到 64，慢连接或无效扫描不会阻塞其它成员的正常 mTLS 请求。
- Python 3.14 环境继续接受旧版 Lun 生成的无 `keyUsage` 根证书，但仅在联邦专用 TLS 上关闭该严格扩展检查；CA 链、mTLS 身份、指纹与事件签名验证仍然必须通过。
- 自动巡检最多 10 路并发，每个地址超时 4 秒，IPv4 优先、IPv6 回退。三次日检失败后，才并发请求候选以外成员的签名复核；多数确认后撤销，两节点使用本机三次失败。票数不足只标记疑似离线，任一可达投票取消本轮撤销。控制面长期停用或端口阻断也属于不可达，旧快照不能证明在线。
- 在线状态是本机最近的可达性观察，不把其它成员的旧快照当作实时在线证明。任何成功的身份绑定 mTLS 直接请求（包括推送快照）都会自动清除本机残留“疑似离线”；更新权限或配置校验错误不再误标离线。较早开始的失败请求不会覆盖其间收到的更新在线证据。不增加心跳，巡检仍每天一次。
- 推送本机更新时，内容相同的脚本和联邦程序不重复写入，联邦程序不重复重启；内容变化后，会有限次等待新版监听就绪才报告更新成功，避免在正常重启窗口内立即继续推送快照。
- 自动撤销先保存永久墓碑并重建本机聚合订阅，再有界广播；通知失败持久化，每 60 秒只重试待补齐成员。接收端无论主动拉取还是被动收到撤销事件，都会刷新聚合文件、排除相关节点。健康轮次不制造事件，不广播，不刷新订阅。恢复的已撤销 VPS 必须生成新身份后重新加入。

## 生命周期

首次在任意 VPS 选择“一键开启本机联邦身份”，Lun 自动分配 TCP 通信端口并放行本机防火墙。普通 VPS 使用空闲高位端口；NAT VPS 必须已有“公网端口-内网端口”映射。任意成员生成加入地址，另一台启用联邦身份的 VPS 粘贴地址即可加入全网。

旧式 API v2 集群可在首次进入时安全迁移。迁移只转换本机状态，保留编号、用户、Token 与订阅快照；不会复制旧共享 CA 私钥，也不会自动访问、刷新、同步或更新旧记录。未重新配对的旧记录必须显示为“待重新配对/未信任”，显式 `add-peer` 后才成为可信 API v3 成员。

启用联邦或完成迁移时，如果完整多用户模块没有启用，Shell 使用当前 UUID、订阅 Token、内网/公网订阅端口、Host、HTTP/HTTPS 与证书参数执行 `init-subscription-only`，安装并启动 `lun-agent`，然后停止 BusyBox 订阅及其 cron/OpenRC 遗留。接管前会保存原 config、服务单元、端口文件和 BusyBox 状态；初始化、监听自检或联邦服务任一步失败都会回退，不能留下半启用联邦。停用联邦时仅订阅模式会被移除并恢复 BusyBox；完整多用户模式和独立网站监控保持不变。

服务器编号从 `01` 起永久保存，不重排、不复用。并发编号冲突由签名事件顺序确定。成员地区可在任意可信成员设置，显示为中文。

## 数据边界

- 协议、端口、NAT、证书、Cloudflare Host/Token/Origin Rules/Tunnel 永远只在目标 VPS 本地保存。
- 协议重建成功后，只广播本机签名订阅快照；每个 VPS 使用相同聚合 Token，但输出自己的公开域名/IP 与订阅端口。
- CDN 优选池同步只传递 `cfip/cdnip` 地址。合并为来源优先并追加目标独有地址；覆盖完全替换目标地址池。每个 `trusted=true` 目标分别执行 `cdn-pool-preview`，经逐台确认后执行 `cdn-pool-sync`；各自独立快照、应用、重建与失败回滚。
- `federation-data` 联邦数据备份不含私钥，可在其它成员合并载入，不替换接收方身份。本机完整 `identity` 备份含密码加密私钥，只能本机灾难恢复；`identity-restore` 会拒绝在线身份重复。

## 手动链式代理

入口：`分布式服务器集群 → 7. 链式代理（手动配置）`。模块默认不创建链路，不增加常驻服务；只有用户确认后才修改选中的两台成员。

自动准备要求两端使用 Lun `V26.10.20.3`、集群 `0.3.3` 和至少 `0.4.2` 的多用户程序。无需预先手动启用 Reality，也不要求开启多用户管理；旧多用户程序不能安全维护链式入站，版本不兼容时会拒绝创建。部署到已有安装时须同步 `lun.sh`、`modules/cluster/lun_cluster.py` 并确认 `modules/multiuser/lun_agent.py` 配套；集群批量更新只分发前两项，不能代替旧多用户程序升级。不要为更新而开启多用户管理或重置用户数据库。

只更新本机主脚本不代表其它 VPS 的集群程序已升级。发布新版后，可在“更新与维护 → 一键更新所有 VPS 代理脚本”同步；旧本机模块若缺少新版链路预检能力，会重新下载校验，不再将旧模块和新主脚本混合下发。未发布或下载到不兼容模块时明确停止，不假报更新完成。

1. 选择“手动新建链路”，输入入口 A、出口 B 的服务器编号。
2. 输入 A 的新内网监听端口；回车自动分配。先预检两端：已有 Reality 时 A 需要 1 个空闲端口，B 不需额外端口；缺少 Reality 时 A 共需 2 个、B 共需 1 个。普通 VPS 遵循已配置端口池（支持 `25001+25010` 或 `25001-25010` 范围），未配置才随机分配；NAT 仅使用已登记、未占用的公网→内网映射。检查核心配置、其他协议、订阅、联邦端口及系统监听；不足时不创建协议，也不擅自修改服务商控制台。
3. 核对预览后回车确认。先远程自动启用缺失的普通 Reality（B 在前、A 在后），使用现有事务重建；只追加新的 Reality 入站，保留旧 Xray 字段与 Sing-box 配置，避免重置自定义路由、WARP 或凭据。随后配置 B 中转身份及 A 独立链路，失败清理两端链式配置，应答丢失也会清理入口。自动准备已成功的普通 Reality 节点作为独立节点保留；失败端由重建事务恢复，不会把已成功添加的普通节点当作垃圾删除。
4. 刷新原有个人、多用户或集群聚合订阅。节点类似 `[日本-大阪1→日本-大阪2]vless-reality-chain-tcp-01-06-abcdef`。客户端只需支持入口的 VLESS TCP Reality，无需自行配置串联。
5. 改变 B 的端口、Reality 密钥或 SNI 后，使用“检查 / 修复链路”读取 B 当前参数并重建。IPv4 公网 IP 同地址族变化沿用已登记成员地址，按需安排本机重建；跨 IPv4/IPv6 切换或 NAT 映射改变应手动修复，不猜测不同地址族的端口。
6. 删除时输入链路所在服务器编号和链路 ID 的至少前 6 位；只移除该链路的标签、路由、中转账户和订阅。部分成员不可达会明确报告，可恢复后重试。停用集群、重置或卸载前须先删除本机链路。

“内部完成”指由 Lun 配置并托管服务器端路由，不代表云厂商免费私网：此版 A→B 使用登记的公网 IP 和加密的 VLESS Reality。两台 VPS 都会产生实际流量和资源占用，速度取决于两段网络和两台机器的能力。

### 数据与安全边界

- 首版只代理 TCP 业务；服务器收到的链路 UDP 明确阻断。Clash 节点标记 `udp: false`，Sing-box 限制 `network: tcp`。客户端本地 DNS、直连规则和未交给代理的流量不受服务端链路控制。
- 普通节点保留，链式节点只加入手动选择器，不自动加入基础订阅的自动测速或负载均衡组。内层目标固定为 B 原有 Reality 入站，不能选择另一条链式入站作为下一跳，避免递归套娃。
- B 使用随机生成、与普通用户 UUID 分离的中转凭据，强制本机直出；B 原有 WARP 和普通节点配置不变。私网、云元数据与 TCP 25 的阻断优先于链路转发，不允许绕过已有阻断规则。
- 多用户权限、有效期和额度按入口 A 生效；链式入站跟随设备增删和协议权限更新。B 的内部身份不映射为用户设备，不重复扣用户额度或记录第二份用户访问明细，但 VPS 服务商仍会统计 B 的真实流量。
- Reality 私钥不离开所属 VPS。B 的中转 UUID 只通过现有 mTLS 返回对应入口 A；不会出现在普通或聚合订阅中，也不作为联邦签名事件全网广播。
- `~/lun/chain_routes.json`、事务快照仅 root 可读写。配置读取异常拒绝继续，不假报成功；回滚失败保留 `.chain-transaction-*` 快照并报告路径。
- 成员被撤销时，聚合器立即过滤依赖该成员的链式节点；现有维护线程在下一轮（最多约 60 秒，服务可用前提下）清理本机转发。旧身份重新加入不会自动复活旧链路，应删除后重建。
- “检查 / 修复”验证配置、服务和订阅重建，不替代用户网络到 A 的实际连接测试。
